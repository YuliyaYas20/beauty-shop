# ADR 0003: Стиль REST API, політика кодів та єдина модель помилок

- **Статус:** Прийнято
- **Дата:** 2026-11-17

## Контекст

Для узгодженої роботи клієнта та сервера, а також для можливості паралельної розробки маршрутів і документації потрібен єдиний стандарт побудови HTTP-ендпоїнтів та обробки помилкових ситуацій.

## Рішення

1. **Contract-First та відповідність OpenAPI:** Публічний інтерфейс сервісу описується у специфікації `docs/api/openapi.yaml`. Усі реалізовані маршрути, назви полів DTO (`id`, `name`, `brand`, `category`, `price`, `description`, `stockQuantity`) та HTTP-статуси повинні строго відповідати цій специфікації.
2. **Стиль REST та політика HTTP-кодів:**
   - `POST /items` — створення ресурсу (`201 Created` при успіху, `400 Bad Request` при помилці валідації).
   - `GET /items` — отримання колекції ресурсів (`200 OK`).
   - `GET /items/{id}` — отримання конкретного ресурсу (`200 OK` або `404 Not Found`).
   - `PUT /items/{id}` — повне оновлення ресурсу (`200 OK`, `400 Bad Request` або `404 Not Found`).
   - `DELETE /items/{id}` — видалення ресурсу (`204 No Content` або `404 Not Found`).
   - `GET /health` — перевірка доступності сервісу (`200 OK`).
3. **Єдиний формат помилок (`ErrorResponse`):** Усі відповіді з кодами `4xx`/`5xx` повертаються у стандартизованому JSON-форматі:
   ```json
   {
     "error": "ValidationError",
     "code": "INVALID_INPUT",
     "details": [
       {
         "field": "price",
         "message": "Price must be greater than or equal to 0"
       }
     ]
   }
   ```
